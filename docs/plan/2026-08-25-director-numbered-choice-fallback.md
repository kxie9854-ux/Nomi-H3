# 导演编号选项兜底

日期：2026-08-25

## 真实摩擦

导演协议要求输出 `:::choices`，但模型偶尔会退化成普通编号列表。用户明明面对一个二选一确认，却只能手打“选 2”，制作关口从一步点击退回成学格式、敲答案。

## 方案取舍

| 方案 | 用户看到什么 | 代价 |
|---|---|---|
| 严格识别末尾编号选项并复用现有卡片（采用） | 普通 `1. / 2.` 确认也变成同款按钮 | 需要保守边界，防止把镜头清单变按钮 |
| 放宽解析所有编号列表 | 几乎都有按钮 | 分镜、步骤、审片清单会被误判，拒绝 |
| 只继续依赖 prompt 纪律 | 偶发时仍只能手打 | 把模型格式波动转嫁给用户，拒绝 |

真正取舍：容错不能以误把内容清单变成操作为代价。宁可漏掉含糊列表，也只把“明确在问用户 + 回答末尾 + 连续 2–5 项”的短列表转成按钮。

## 实现范围

1. `:::choices` 仍是最高优先级和唯一结构化协议。
2. 无 fence 时，只识别回答末尾连续的 `1. / 2.`、`1、/ 2、`、`(1) / (2)` 列表。
3. 必须连续从 1 开始、2–5 项、每项单行且标签不超过 80 字。
4. 列表前最后一段必须是明确的提问/确认语义；普通步骤、镜头表、参数清单保持纯文本。
5. fallback id 使用可回传的数字字符串，点击仍走现有 `formatDirectorChoiceReply`。
6. 完全复用现有 `DirectorLine` 选项按钮，不新增组件、CSS、i18n 文案或第二套交互。

## 不动项

- 不解析历史消息为可点击按钮；历史只读边界保持不变。
- 不解析项目符号、Markdown 表格、镜头编号或段落中的列表。
- 不改变 spend / approval / elicitation 授权语义。
- 不修改导演 skill 的正式 `:::choices` 协议。

## 回滚

删除 fallback 解析分支即可恢复 fence-only；正式协议、UI 与发送链路不受影响。

## 验收

- 明确提问 + 末尾 2/3 个编号选项 → 正确按钮、正文不重复列表。
- `:::choices` 优先，内部数字标签不受 fallback 干扰。
- 分镜清单、制作步骤、非末尾列表、编号不连续、6 项、超长行 → 不生成按钮。
- streaming 的半截 `:::choices` 仍隐藏且不得被 fallback 抢解析。
- 针对性测试、全门禁与现有真实导演恢复走查保持通过。

## 样张说明

本改动不引入新视觉：输出仍是已获批并已真机使用的现有选项按钮。这里的可见变化只有“同一按钮能承接模型的编号格式降级”，因此以现有真实组件作为样张真相源，不复制第二份 HTML 布局。

## 执行结果

- 已在 `directorChoices.ts` 增加严格末尾编号决策解析；正式 `:::choices` 与 streaming 半截 fence 始终优先。
- 支持 `1.`、`1、`、`(1)` 三种常见写法，回传稳定数字 id，点击仍走现有选项回复格式。
- 已锁死误判边界：普通制作步骤/镜头清单、非末尾列表、断号、6 项、超长标签均不生成按钮。
- 针对性回归 6 files / 39 tests 全过。
- 真机验收顺带修复共享 Electron 启动器的假超时兜底：优雅关闭卡住时只强制终止本次启动的 child；两条 mock 测试与真实预览页 `exit 0` 锁死。
- 最终全门禁：filesize / tokens 0/0/0/0 / i18n 零硬编码 / lint 98 warnings 棘轮 / 双 TypeScript / Vitest 680 passed + 1 skipped、6069 passed + 1 skipped / pnpm 10.8.1 production build 全绿。
