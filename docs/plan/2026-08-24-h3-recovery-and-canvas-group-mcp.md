# H3 断线续查与画布分组 MCP（2026-08-24）

状态：✅ 已交付

## 现状与根因

- H3 提交成功后，MCP 生成路径把远端 `taskId` 只留在主进程任务缓存；轮询 `fetch` 断线时，画布节点只落通用 `error`。
- 下一次调用看不到已提交任务，只能重新下单，存在重复扣费风险。当前测试节点已出现两条 `vendor.call.requested`、无完成事件，证明不是理论风险。
- 多镜制作仍只会新增节点/连线；MCP 没有建立画布分组的能力，简报、角色、分镜和成片会摊在同一平面。

## 范围

### A. H3 可恢复闭环

1. 异步供应商首调拿到 `taskId` 后，先把 task 身份、任务类型与运行态持久化到节点，再开始轮询。
2. 轮询网络失败时收敛为 `recoverable`，保留明确错误；再次调用同节点优先续查现有任务，不重新确认、不重新提交。
3. 兼容本次旧节点：从已有 AutoDL result URL 错误中恢复 taskId，仅用于迁移已经产生的悬空任务。
4. 续查成功后正常本地化资产、回写原视频节点；随后排入时间轴并真导出 MP4。

### B. 画布分组 MCP

1. 在能力核增加单一 `groupNodes` 领域操作，复用现有画布 group 数据结构与布局语义。
2. 暴露 `nomi_group_nodes`：输入项目、标题、节点 IDs；返回 group ID、实际成员与跳过项。
3. 导演多镜流程按项目简报 / 角色与场景 / 分镜制作 / 成片分组，不创建平行制作线。
4. 读取画布时给 agent 返回精简 group 视图，后续能复用而不是重复建组。

## 不动项

- 不改变 AutoDL H3 官方端点、鉴权、工作流 ID、5 秒/480p 最低档和首尾帧模式。
- 不自动重试 `submission_unknown`；拿不到 taskId 时仍诚实停住。
- 不重做现有画布分组 UI，不新增全局 CSS，不改变手工分组行为。
- 不改时间轴编辑与导出格式；只验证现有正式入口。

- 分组：移除新工具与领域操作；`groups` 是现有项目字段，已创建分组仍可由现有 UI 打开或解组。
